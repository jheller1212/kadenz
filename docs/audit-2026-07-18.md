# Kadenz audit — plan of attack

## Verdict

The core product is in good shape architecturally (typed Drizzle layer, outbox pattern, offline queue, plan engine with tests), but the audit found a consistent failure mode: **the last mile is unwired**. The outbox has idempotency but never resets keys, so GCal sync dies after the first update. The Garmin worker accepts `rep_distance_meters` but never reads it, so every interval workout reaches the watch as lap-button steps. The offline cache exists but one bad silent refresh replaces the Today screen with "no plan". Profile scoping is applied everywhere except three queries, which lets household members delete/complete each other's sessions. None of these are design problems — they're 1-to-20-line fixes — but four of them (GCal staleness, Garmin intervals, offline self-destruct, race-date off-by-one-week) break headline features for real users today. The plan engine race-date bug and the profile-scoping holes are the ones that will actively erode trust in the app.

## Feature-level suggestions

1. **Illness/injury/rest-day toggles on the wellness check-in.** The readiness engine already implements hard caps (25/35) for these flags and the API accepts them — no client ever sends them, and the upsert wipes them. Two toggles + a partial-update PUT turns dead code into the readiness feature Benchmark can't match from a watch.
2. **Pain overlay on the exercise history detail chart.** The API already computes the pain timeline and e1rm points "so the UI can overlay" them, and the list page already draws the dots. Rendering what's already fetched completes the Achilles story the app is built around.
3. **Sync health card.** `sync_outbox` already records status + lastError for every GCal/Garmin job and the worker distinguishes auth-dead from up — nothing reads it. A small "last sync / N failed / Reconnect Garmin" strip in settings converts three silent-failure classes into user-visible, self-serviceable states.
4. **True offline-first Today.** The cache, offline queue, and snapshot mechanisms all exist; they're defeated by the refresh catch, the bypassing CTA, and the fire-and-forget set logging. Fixing those three (already in Fix now) plus a small "offline — showing cached plan" banner makes kadenz a genuinely gym-basement-proof PWA — the cheapest big UX win available.
5. **Per-exercise rest as a real training variable.** Once the guided session honors `ex.restSeconds` (Fix soon), estimates, the overview labels, and the builder's 30/60/90 picker all become truthful — and it opens the door to rest auto-progression (shorter rest as e1rm climbs), which the data model already supports.
